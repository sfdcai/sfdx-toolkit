# SFDX DevOps Toolkit v0.2.0 Release Notes

**Release Date:** November 25, 2026  
**Build:** v0.2.0-prod  
**Platform:** Next.js 14, TypeScript 5, Tailwind CSS, Salesforce CLI (sf)

---

## 🚀 Overview

The SFDX DevOps Toolkit v0.2.0 introduces an enterprise-grade **5-Tier Dependency-Ordered Deployment Pipeline**, autonomous **Digital Experience & LWR companion bundle packaging**, an **AST Pre-Flight Dependency Validator**, and seamless **Multi-Pass Layered Staging** to eliminate common Metadata API deployment failures.

---

## 🌟 Key Features & Architectural Enhancements

### 1. 5-Tier Dependency-Ordered Deployment Engine
Salesforce Metadata API deployments often fail when inter-dependent components (e.g., Layouts referencing QuickActions, Triggers referencing Platform Events, or Flows referencing Workflow Alerts) are deployed in a single un-ordered batch. Toolkit v0.2.0 formalizes a strict dependency sequence:
- **Phase 1: Foundational Schema**: Custom Objects, Custom Fields, Global Value Sets, Standard Value Sets, Custom Metadata Types.
- **Phase 2: Business Processes & Record Types**: Lead/Case processes, record types dependent on custom fields.
- **Phase 3: Foundational UI Artifacts**: Custom Labels, Content Assets, Static Resources, WebLinks, Compact Layouts, Page Layouts, FlexiPages, Custom Tabs, Applications.
- **Phase 4: Automations & Code Execution**: Platform Events, Custom Metadata Records, Apex Classes, Apex Triggers, Lightning Web Components (LWC), Aura Bundles, Email Templates & Folders, Workflow Alerts, Flows, Quick Actions.
- **Phase 5: Security & Access Governance**: Custom Permissions, Permission Sets, Permission Set Groups (PSG), Profiles, Sharing Rules, Remote Site Settings, Report Types.
- **Phase 6: Digital Experience Cloud**: LWR Sites, Digital Experience Bundles, and Experience Configurations.

### 2. Autonomous Companion Bundle Packaging
- Digital Experience (`digitalExperiences`) and Experience Bundle (`experiences`) contain nested file trees (`content.json`, `_meta.json`, `styles.css`) for views, routes, and themes.
- Enhanced `expandStagePaths` in `src/lib/deploy.ts` now automatically detects and includes all recursive bundle companion files when staging delta manifests.

### 3. AST Pre-Flight Dependency & Package Isolation
- **AppExchange Package Isolation**: Scans source code and manifests for third-party namespaces (e.g. `purecloud` / Genesys Cloud). If the target org lacks the package, uninstalled class implementations and utility bar entries are isolated before deployment.
- **Platform Event Schema Prioritization**: Automatically prioritizes Platform Event objects (`*__e`) and fields so triggers compiling against `Schema.<Event>__e` succeed on first pass.
- **Email Folder Membership Invariant**: Automatically injects parent folder members into `<name>EmailTemplate</name>` manifests to prevent `Cannot find folder` errors.

### 4. Non-Destructive Multi-Pass Layered Deployment
- Corrected staging workspace logic during layered deployment passes (`sourcePath: undefined`) to prevent catastrophic workspace wipes between deployment passes.
- Full support for sandbox dry-run pre-flight validation (`sf project deploy start --dry-run --test-level NoTestRun`).
